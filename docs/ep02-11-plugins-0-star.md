## 四件事，我承认

**1. 我把"做出来"当成了"有人要"。**
代码推上去了，README 写了，安装一行命令。然后我以为结束了。其实那只是"备货"，货架上没有顾客经过。

**2. 我选的场景全是我自己的摩擦。**
重启坞、发布器、泄漏守卫、翻译器——每一个都解决我一天里真实撞上的问题。所以它对我有用，这是真的。但对一个陌生人来说，它的第一句是"这跟我没关系"。

**3. 我赌的是搜索，但我写的是说明书。**
README 写的是"我做了什么"。搜索的人找的是"我遇到了什么问题"。这两个字符串几乎不重叠。

**4. 我没有一个三秒版。**
"这个工具在什么情况下让人疼，它怎么止疼"——这句话我一直没写过。没有它，任何分发都是把链接扔进人堆。

## 换的做法（可以直接抄）

- **每个项目一句话**：谁、在什么情况下会疼、这东西怎么止疼。不是"基于 X 的 Y 工具"。
- **先发问题，再发工具**：一段真实的翻车过程讲完，工具自己出场。视频、帖子都按这个结构。
- **一次只推一个**，推的时候安装就是一句话。
- **"有人在评论区问这怎么弄"才算需求**。在出现这句话之前，不做第二个功能，也不谈收费。

### 两个我自己踩过的坑，写给别人避

**坑一：`rembg.remove()` 会动你的 RGB。**
它不只返回 alpha，重采样/去污染会把彩色像素压向灰背景色。我的立绘一上深色背景就变成一层蓝雾。
正确做法：只要蒙版，RGB 自己留着——

```python
mask = remove(img, session=sess, only_mask=True, alpha_matting=False)
res = img.convert("RGBA")
res.putalpha(mask)
```

**坑二：老版本 ffmpeg 的 `amix` 会按输入数衰减。**
两个输入混完，人声整体掉 3 dB，测出来 mean_volume 从 -20.5 掉到 -26.2；而且 2018 那个构建里 `normalize=0` 这个选项根本不存在，写上去直接报错。
最省事的解法是别用 amix：两个音轨解成 numpy 相加，然后整体归一到 -1 dBFS。

```python
mix = voice + bgm * 0.16
mix = mix * (0.89 / abs(mix).max())
```
