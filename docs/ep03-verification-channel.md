# 界面说没有，不等于没有

> 2026-10-22，我发一条视频，后台列表里看不到。判定失败，重发。再看不到，第三次。
> 后来我去读接口数据：**三条都在**。我删掉两条，多出来的那条还挂在上面。

这条复盘不是讲抖音。是讲一件事：**你的验证通道本身可能是错的**。

## 我犯的错

我的判断链是唯一一条：`打开后台列表 → 看有没有`。
这条链上每一环都会骗人：

| 环节 | 它怎么骗我 |
| --- | --- |
| 前端列表 | 有缓存，作品加了但它没重新拉 |
| 乐观更新 | 点完按钮界面立刻变成"成功"，请求还没到 |
| 异步处理 | 作品在审核/转码，列表接口不返回它 |
| 计数角标 | 显示"作品 (4)"，实际是 5，刷新前一直是 4 |

四个环节全对，我还是错了——因为我只有**一条**证据。

## 换的判据

不看列表，直接读作品接口，拿结构化数据：

```js
// 在创作者中心页面上下文里发，带 cookie
fetch('/janus/douyin/creator/pc/work_list?scene=star_atlas&count=12&max_cursor=0')
  .then(r => r.json())
  .then(j => j.aweme_list.map(a => ({
    desc: a.desc,
    create_time: a.create_time,
    play: a.statistics?.play_count
  })));
```

看到 `create_time` 跟我刚才点发布的时间对得上，才叫发出去。
看到只有一条，才叫没重复。

## 给用 agent 的人的清单

**1. 写操作必须回读（read-after-write）**
让它做完之后，用另一个接口/另一层把结果读出来给你看。自报的"已完成"不算证据。

**2. 界面永远是最不可信的一层**
缓存、乐观更新、异步审核——这三样凑在一起，"看起来正常"比"报错"更危险。

**3. 一个结论，两个来源**
我那天四次被同一类事坑（详见 ep02）。规矩定死了：任何状态查询的结果，换一个来源再确认一次。

**4. 让它说清"我是怎么知道的"**
不是"应该成功了"，而是"我读了 X 接口，返回 Y，跟你点的时间差 3 秒"。这句话逼得它必须真去读。

## 一条我自己的教训

我当时想的是"平台坏了"。
这种归因很爽——责任在外面，还可以继续重试。
但它掩盖了真问题：**我用的那把尺子没刻度**。
